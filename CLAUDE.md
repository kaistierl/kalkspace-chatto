# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

The repo currently contains only the design spec, `docs/design.md` (in German). No implementation exists yet. Treat that document as the source of truth for what to build. When an implementation decision differs from it, update the design doc in the same change.

## What this is

This is infrastructure-as-code for a proof of concept: a self-hosted [Chatto](https://docs.chatto.run) server (Slack alternative) for Kalkspace. It runs on a single Hetzner Cloud VM. The PoC runs under `chat.cyb3rk4t.me` in Kai's Hetzner project. If the PoC is approved, the same repo is redeployed under `chat.kalk.space` in Kalkspace infra. So everything environment-specific (Hetzner token, domain, owner email, SMTP, server type) must be a variable or a vault secret, never hardcoded.

## Architecture (three layers, strict boundaries)

1. **OpenTofu (`terraform/`, `hcloud` provider):** creates the server, Primary IPv4/IPv6, Volume (attached via a separate attachment resource), Cloud Firewall and SSH key, and outputs the Ansible inventory. The state is local and gitignored. There is no cloud-init: Hetzner injects the root SSH key, and Ansible does the rest.
2. **Ansible (`ansible/`):** sets up the host and deploys. Roles: `base`, `volume`, `docker`, `chatto`, `backup`, `beszel`. Secrets live only in `group_vars/all/vault.yml` (Ansible Vault). The vault password file sits outside the repo and is referenced from `ansible.cfg`.
3. **Docker Compose (`compose/`):** runs Caddy (TLS) → Chatto → NATS JetStream, plus LiveKit for calls. There is no Postgres: all Chatto data, **including attachments**, lives in NATS JetStream. It is bind-mounted from the Hetzner Volume at `/srv/chatto`. Call media bypasses Caddy and goes straight to LiveKit (UDP 7882, UDP 3478, TCP 7881).

## Invariants to preserve

- **Never `docker compose down`** (it stops NATS), in Ansible or anywhere else. Use `docker compose up -d`. Never copy `/srv/chatto/nats` while it is running.
- **Upstream files stay unmodified:** `compose/compose.yml`, `Caddyfile` and `nats-server.conf` are copied verbatim from Chatto's `examples/dockercompose` (v0.5.0). Each gets a header comment giving its origin and version. All customization goes into `compose.override.yml`, `env.j2` and `livekit.yaml.j2`, so upstream updates stay a clean diff.
- **Image versions are pinned** (Chatto `0.5.0`, NATS, LiveKit, Caddy, Beszel agent) as variables in `vars.yml`, never `latest`.
- **Rebuild safety:** Ansible must run against a fresh VM with an existing Volume without touching existing data. Volume and Primary IP have `prevent_destroy` plus Hetzner delete protection. Mount the Volume via `/dev/disk/by-id/…`, not Hetzner automount.
- **Secrets are generated by Ansible on the first run** and stored in the vault, not by upstream's `init-env.sh`. This keeps them stable across rebuilds. `.env` and `livekit.generated.yaml` are rendered from the vault on every deploy.
- **The Hetzner Cloud Firewall is the only filter** (there is no host firewall). Docker may publish only the ports listed in the design doc's firewall table. NATS (4222) and Chatto (4000) must never be exposed.
- **Feature flags** in `vars.yml`: `chatto_push_enabled`, `chatto_direct_registration`, `backup_offsite_enabled`, `beszel_agent_enabled`. LiveKit is mandatory and has no flag.
- **`reset.yml`** (it wipes NATS data) only runs when the environment is marked as test, and it asks for confirmation first.
- **Slack exports and import archives** contain private data and must never be committed.

## Commands (planned)

All operator commands go through a root `justfile` (not a Makefile): `just plan`, `just apply` (OpenTofu), `just deploy` (Ansible), `just backup-now` and `just restore <archive>`. `just --list` shows all recipes. Use them once they exist. Multi-step recipes should be written as shebang (`#!/usr/bin/env bash`) recipes rather than line-by-line. Bootstrap order matters: `apply` → set the DNS records and confirm they resolve → `deploy` → immediately complete Chatto's setup wizard. Caddy's ACME fails without DNS, and the first visitor can become owner until the wizard is done.
